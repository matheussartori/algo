Every lesson follows the same routine. The order is on purpose: each part catches a different way of thinking you get it when you don't quite yet.

1. **Intuition.** It starts with an everyday problem and the idea that solves it, before any code.
2. **Visualization.** The algorithm runs step by step, with the current line highlighted and the variables beside it.
3. **Prediction.** Before each step, you guess what comes next. Just watching gives you a nice "got it" feeling, but guessing is where you find out if you really do.
4. **Practice.** Exercises with tests. Some of them are hidden, so you think about the annoying cases instead of just making the visible ones pass.
5. **Review.** A few quick questions to answer from memory. Pulling things back out of your head sticks much better than re-reading.

## About the exercises

- Pick **TypeScript** or **JavaScript** at the top of the editor. Your choice and your code are saved in this browser.
- **⌘/Ctrl + Enter** runs the tests.
- Stuck? Give it about 20 minutes before asking for a **hint**. They start as a small nudge and get closer to the answer.
- The **solution** only shows up after you've run the tests at least once. Peeking is fine, just close it and write it again from memory.

Your code runs in a **Web Worker**, away from the page. So an infinite loop won't freeze anything, it just gets cut off after 3 seconds.
