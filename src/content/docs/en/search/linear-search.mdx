## The idea

You lost your key in a row of drawers. With no clue at all, the only sure way is to open one drawer at a time, first to last, until you find it.

That's **linear search**. You go through the elements in order and compare each one with the target. It works on **any** array, sorted or not.

## Cost

| Case | Comparisons | When it happens |
| --- | --- | --- |
| Best | 1 | The target is the first element |
| Worst | n | The target is last or missing |
| Average | ~n/2 | The target is at a random position |

Time grows in proportion to the array, so it's **O(n)**. The only extra memory is the variable `i`, so **O(1)**.

## Where you already use it

In JavaScript, `Array.prototype.indexOf`, `includes`, `find` and `findIndex` are linear searches. They're fine for small arrays or a one-off lookup. If you'll search the same large array many times, a `Set` or `Map` (O(1) lookup on average), or a sorted array with [binary search](/en/search/binary-search/), usually pays off.
