## The idea

Picture a game. I pick a number from 1 to 100 and you try to guess it. After each guess I say "higher" or "lower". Starting at 1 and counting up works, but it can take 100 guesses. Guess **50** and you rule out half the options at once. Then 25 or 75, and so on. You'll get it in **7 guesses** at most.

**Binary search** does that on a **sorted** array. It keeps a range `[low, high]` where the target can still be and, at each step, looks at the middle element:

- If it is the target, we are done.
- If it is **smaller** than the target, the target can only be to the right: `low = mid + 1`.
- If it is **larger**, it can only be to the left: `high = mid - 1`.

:::caution[Only works on a sorted array]
Without the sorting, one comparison can't throw away a whole half.
:::

## The invariant

To write a binary search without bugs, you need to know what **never changes** during the loop:

> If the target is in the array, it is between `low` and `high` (inclusive).

Every update keeps this true. `low = mid + 1` only happens when `array[mid] < target`, so nothing left of `mid + 1` can be the target. When `low > high`, the range is empty, and the invariant tells you the target isn't there.

The most common bugs break this invariant:

- `while (low < high)` instead of `<=` skips the last element left.
- `low = mid` instead of `mid + 1` can stop the range from shrinking, and then it loops forever.

## Cost

Each step halves the range. With n elements, after k steps you have n / 2^k left, which hits 1 when k = log₂ n.

| n | Linear search (worst) | Binary search (worst) |
| --- | --- | --- |
| 100 | 100 | 7 |
| 1,000,000 | 1,000,000 | 20 |
| 1,000,000,000 | 1,000,000,000 | 30 |

Time is **O(log n)** and extra memory is **O(1)**.

## Where it shows up

- **`git bisect`** finds the commit that introduced a bug by running a binary search over the history.
- Database indexes (B-trees) use the same idea to find one row among millions.
- Lodash's `_.sortedIndex` and Python's `bisect` find where to insert a value without breaking the order.
- It works outside arrays too. "What's the smallest batch size that doesn't run out of memory?" can be solved by halving the range of answers.
