## The idea

Think of a game: I pick a number from 1 to 100 and you try to guess it. After each guess I say "higher" or "lower". Starting at 1 and counting up works, but it can take 100 guesses. Guessing **50** rules out half the options at once. Then 25 or 75, and so on. You will get it in at most **7 guesses**.

**Binary search** does exactly that on a **sorted** array. It keeps a range `[low, high]` where the target can still be and, at every step, looks at the middle element:

- If it is the target, we are done.
- If it is **smaller** than the target, the target can only be to the right: `low = mid + 1`.
- If it is **larger**, it can only be to the left: `high = mid - 1`.

:::caution[Only works on a sorted array]
Sorting is what lets one comparison discard a whole half.
:::

## The invariant

The secret to writing a bug-free binary search is knowing what **never changes** during the loop:

> If the target is in the array, it is between `low` and `high` (inclusive).

Every update preserves this. `low = mid + 1` only happens when `array[mid] < target`, so nothing left of `mid + 1` can be the target. When `low > high`, the range is empty and the invariant guarantees the target is missing.

The most common bugs break exactly this invariant:

- `while (low < high)` instead of `<=`: skips the last remaining element.
- `low = mid` instead of `mid + 1`: the range may stop shrinking and loop forever.

## Cost

Each step halves the range. Starting with n elements, after k steps n / 2^k remain. That reaches 1 when k = log₂ n.

| n | Linear search (worst) | Binary search (worst) |
| --- | --- | --- |
| 100 | 100 | 7 |
| 1,000,000 | 1,000,000 | 20 |
| 1,000,000,000 | 1,000,000,000 | 30 |

Time **O(log n)**, extra memory **O(1)**.

## Where it shows up

- **`git bisect`** finds the commit that introduced a bug by binary searching the history.
- Database indexes (B-trees) apply the same idea to find one row among millions.
- Lodash's `_.sortedIndex` and Python's `bisect` find where to insert a value while keeping order.
- Beyond arrays: "what is the smallest batch size that does not run out of memory?" is also solved by halving the range of answers.
